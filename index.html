What this tab shows: every device needs an address, like a house needs a street address. Each zone has its own street (192.168.10.x for Ticketing, 192.168.20.x for Payments and so on). Most devices get an address automatically from the Main Switch (DHCP); servers keep a fixed one.

Zones and their address ranges

Every zone uses a /24 range, meaning 254 usable addresses. Addresses .1 to .20 are kept for fixed devices: .1 is always the zone's exit door (gateway), servers use .10 and .11, the WiFi access point uses .5. Automatic addresses start at .21. A real stadium would give fans a much larger range, or several WiFi zones; one /24 keeps this lab model simple.

What this tab shows: two kinds of protection. Rule lists (ACLs) sit at each zone's exit door and decide which messages may leave the zone. Port security makes each switch socket remember its device and lock itself if a stranger plugs in.

Who can reach whom

Read across: the row is the sender, the column is the receiver. Worked out live from the rule lists below, using pings, secure web, web and name lookups.

Rule lists at each exit door

Rules are read top to bottom and the first one that matches wins. Anything that matches no rule is blocked. Replies are checked on their way back too. "Matches" counts how often each rule was used.

What this tab shows: the stadium's Internet link carries 100 Mbps. When a goal is scored, thousands of fans upload at once and the link fills up. Without a fast lane the live TV feed gets stuck in the same queue and breaks up. With the fast lane (QoS) the TV feed always goes first, payments get a reserved share, and fans use what is left.

Each fan adds about 0.01 Mbps of traffic, so 40,000 fans want 400 Mbps: four times what the link can carry.

Limits of this simulator

      
It models zones, routing between zones, automatic addresses, rule lists (including replies), socket locks and a queue model for the fast lane. It does not run real Cisco software, spanning tree or routing protocols. Delay and loss figures come from a simple model, so they show the effect rather than exact numbers. The Device setup tab lets the same design be built on real equipment.
